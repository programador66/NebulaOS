# NebulaOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dotfiles para Ubuntu 24.04 e uma CLI `nebula` que abre sessões de Claude Code (com sub-agentes em painéis tmux) ou Codex dentro do Deepin Terminal.

**Architecture:**
- `bin/nebula` é um script bash que gerencia sessões tmux. Cada sessão tem um painel líder com o agente e um hook de sessão que mantém o layout `main-horizontal`.
- Os dotfiles (zsh, starship, tmux) são aplicados com GNU Stow por scripts numerados, como no AntaresOS.
- A configuração do Deepin Terminal é ajustada pontualmente: o tema por edição de INI e o shell via D-Bus.

**Tech Stack:** bash, tmux 3.4, GNU Stow 2.3.1, zsh 5.9 + Oh My Zsh, starship, bats 1.10, shellcheck 0.9, Deepin Terminal 5.9.

**Spec:** `docs/specs/2026-11-10-nebulaos-design.md`

## Global Constraints

- Alvo: Ubuntu 24.04, X11, Deepin Terminal 5.9.x. Pacotes apt: `zsh tmux stow git curl` (runtime) + `bats shellcheck` (dev).
- Todo script é bash com `set -euo pipefail` (exceto arquivos `source`ados por zsh) e passa em `shellcheck` sem avisos.
- Nunca tocar: `~/.claude/settings.json`, shell de login (sem `chsh`), configurações existentes de git e SSH.
- Arquivo real que conflite com o stow → renomear para `<arquivo>.nebula-bak` antes de linkar.
- Comando do líder Claude: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 claude --teammate-mode tmux` (variável só nesse processo).
- Layout: `main-horizontal`, `main-pane-height 55%`.
- Cores: verde `#00cd00`, fundo `#000000`, borda inativa `#303030`.
- Tema Deepin: `[basic.interface.expand_theme] value=Theme8`.
- Mensagens ao usuário em português. Exit 2 para uso incorreto, 1 para erro de ambiente.
- Commits com `Caio Lacerda <kaio.cesr@gmail.com>` (já configurado localmente no repo).

## Review Focus

1. Rodar `nebula claude x` estando **dentro** de uma sessão tmux. Esperado: `switch-client`, sem aninhar (teste na Task 3).
2. Retomar uma sessão criada em outro diretório. Esperado: retoma e avisa sobre a diferença, sem recriar (Task 3).
3. Split feito por um processo externo, como o Claude chamando `tmux split-window`, numa sessão nebula. Esperado: layout reaplicado. Split numa sessão tmux não-nebula: layout intocado (Task 4).
4. Rodar `install.sh` duas vezes, ou com `.zshrc` real existente. Esperado: backup único, sem erro, links corretos (Task 6).
5. `codex`/`claude` instalados via nvm ou `~/.local/bin` e invisíveis num zsh novo. Esperado: o `.zshrc` carrega nvm e `~/.local/bin` (Task 5).

### Ganchos de teste do `bin/nebula` (variáveis de ambiente)

| Variável | Efeito |
|---|---|
| `NEBULA_TMUX_SOCKET` | Se definida, todo `tmux` vira `tmux -L "$NEBULA_TMUX_SOCKET"` |
| `NEBULA_NO_ATTACH=1` | Não faz `attach`/`switch-client`; imprime `would-attach <nome>` ou `would-switch <nome>` |
| `NEBULA_ROOT` | Raiz do repo (padrão: diretório pai de `bin/`, resolvendo symlink) |
